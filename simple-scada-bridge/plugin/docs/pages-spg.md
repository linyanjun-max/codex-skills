# Pages.spg — формат экранов Simple-Scada 2 и как с ним работать

Всё ниже получено экспериментально на **Simple-Scada 2.7.3.1 (Demo-64)**: образцы
рисовались в редакторе, затем файлы сопоставлялись побайтово (diff двух объектов,
отличающихся одним свойством). Ничего не угадано — каждый offset проверен тем,
что сервер после записи грузит страницу без ошибок.

Реализация: `lib/binfmt.js` → `parsePages()` (чтение) и `editPages()` (запись).

## 1. Структура файла

```
Pages.spg = [заголовок страницы][подстраница][u32 count][записи объектов][хвост]
```

* `count` — число объектов; лежит ровно за 4 байта до первой записи объекта
  (в пустой странице файл кончается сразу после него).
* запись объекта:

```
u16 type | u32 len(name) | name (ASCII) | body
```

* `type 0` — служебные записи: `PageN`, `SubpageN`, а также **внутренние части
  составных компонентов** (`Scale`, `Field` у «Уровня»). Они идут сразу за
  родителем и входят в его диапазон.
* `type 1..18` — объекты экрана.

| type | компонент | type | компонент |
|---|---|---|---|
| 1 | Изображение | 10 | Временные тренды |
| 2 | Фигура | 11 | Заслонка |
| 3 | Трубопровод | 12 | Линия |
| 4 | Текст | 13 | Флажок |
| 5 | Поле | 14 | Список |
| 6 | Шкала | 15 | Таблица |
| 7 | Кнопка | 16 | Календарь |
| 8 | Резервуар | 17 | Список сообщений |
| 9 | Уровень | 18 | Расписание |

## 2. Поля записи

`body = offset + 6 + len(name)`. Смещения **относительно body**, поэтому имя
объекта может быть любой длины — вычислять их от начала записи нельзя.

| Смещение | Поле | Тип |
|---|---|---|
| body+8 | X, Y, W, H | 4 × float32 |
| body+40 | цвет шрифта | 3 байта **BGR** |
| body+45 | цвет заливки | 3 байта BGR |
| body+107 | порядковый id объекта | u32, +4 на объект |
| body+111 | основная переменная | `[u32 index][u32 0]`, нет = `FF × 8` |
| body+127 | вторая переменная («Доп. переменная») | то же |
| body+137 | Текст: подпись | `u32 len` + UTF-16LE |
| body+141 | цвет границы | 3 байта BGR |
| body+151 / +219 | Кнопка: имена состояний 1 и 2 | `u32 len` + UTF-16LE |
| body+171 / +235 | Кнопка: тексты состояний 1 и 2 | `u32 len` + UTF-16LE |

**Индекс переменной** (body+111) — это номер строки переменной в её группе,
начиная с нуля: в проекте КП `rVib=0, bAckCmd=1, … bManualMode=20`. Проверено
сопоставлением: `fA` (рисовался на `rVib`) содержит `0`, `fB` (на `rTemp`) — `15`.

## 3. Грабли, на которые уже наступили

### 3.1 Никогда не искать id «по диапазону»

Первая версия искала `u32` в диапазоне `0x2400..0x2800` по всей записи. Это
ломает чужие поля:

* длина строки 36–40 символов даёт `0x000024xx..0x000027xx` — попадёт в диапазон
  (в счёт идёт окно, начинающееся на байт раньше поля длины);
* цвет `#24303A` (BGR `3A 30 24`) с соседним нулём даёт `0x00002430`.

Симптом на стороне сервера и редактора:

```
Ошибка при загрузке страниц проекта! Stream read error | subpage Subpage1 | page Page1
```

Правило: **id писать и читать только по `body+107`**, никакого поиска.

### 3.2 Составные компоненты

«Уровень» — это родительская запись + две служебные (`Scale`, `Field`) с type 0,
у которых своя геометрия. Клон обязан копировать диапазон до следующей записи с
`type != 0`; иначе после вставки сервер читает мусор.

### 3.3 Размер страницы — 1280×720, а не 1600×900

Клиент масштабирует страницу под экран (на 2560×1440 — ровно ×2). Раскладка,
сделанная «на 1600×900», обрезается справа и снизу, а крупный шрифт (20 pt)
после ×2 превращается в 40 pt и всё разъезжается. Проектировать надо в
**1280×720**, шрифты 9–12 pt.

### 3.4 Шрифт наследуется от образца

Отдельного «простого» поля размера шрифта не нашли: у компонента есть блок шрифта
(имя, размер, начертание) внутри той же записи. Практический приём — держать в
шаблонном проекте по одному образцу каждого типа с нужным шрифтом и клонировать
их; тогда генератор вообще не обязан знать про шрифты.

Метрики шрифта и проверенная раскладка экрана — в `screen-layout.md`.

## 4. Редактор, сервер, клиент — правила совместной жизни

* **Editor.exe держит проект в памяти.** Если записать `Pages.spg` (или
  `Scripts.ssc`) снаружи, пока проект открыт в редакторе, следующее сохранение
  затрёт изменения — проверено: файл вернулся с 2731 к 23 байтам. Писать только
  при закрытом редакторе; после записи открыть проект заново (он читается с диска).
* **Сервер читает список проектов при старте.** Новый каталог проекта появится в
  `scada_run` только после перезапуска `Server.exe`.
* **Demo-64 разрешает один запущенный проект.** Перед запуском следующего
  предыдущий надо остановить.
* **Компиляция скриптов** — только в редакторе (`Ctrl+Shift+S`); сервер исполняет
  `Scripts\Compiled\program.exs`, поэтому правка `Scripts.ssc` без перекомпиляции
  ничего не меняет.

## 5. Как проверять страницу без редактора

Цикл, которым отлаживался этот формат (не требует участия человека):

1. записать файл страницы;
2. перезапустить `Server.exe` (или взять уже зарегистрированный проект);
3. `scada_run start проект`;
4. прочитать хвост `Logs\Server-log.txt`:

```
... | проект | активирован                <- страница прочиталась
... | проект | Ошибка при загрузке страниц проекта! Stream read error | ...
```

5. визуально — `scada_run start` с `client: true`, затем `PrintWindow` окна
   `Client.exe` (обычный `CopyFromScreen` бесполезен: окно не выходит на передний
   план, и снимок получается чужого окна).

Приём для быстрой итерации: перезаписать `Pages.spg` **уже зарегистрированного**
проекта и сделать `restart` — перезапуск сервера не нужен, страницы читаются
заново при каждой активации.

## 6. Что известно про остальные файлы

| Файл | Состояние |
|---|---|
| `Variables.svr` | разобран: группы, строки, описания; правка описания/формата |
| `Scripts.ssc` | разобран полностью: Pascal (PaxCompiler), записи идут как есть |
| `Pages.spg` | разобран (этот документ); чтение и правка объектов |

| `Messages.smg` | не разобран (список сообщений) |
| `Trends.str` | не разобран (тренды) |

## 7. Скрипты: важное

* Язык — **Pascal** (`begin … end.`), Object Pascal через PaxCompiler.
* Событие привязывается **не по имени скрипта**, а свойством события объекта
  (`OnDataChange`, `OnClick`, `OnEnter` страницы: `Панель страниц → Page1 → OnEnter`).
  Имя вида `BellShape_OnDataChange` редактор просто генерирует сам. Поэтому код
  можно подготовить заранее, а привязку всё равно надо сделать в редакторе.
* `GetUserName` / `GetClientName` работают только в скриптах, вызванных клиентом
  (`OnClick`, `OnDataChange`); в скриптах «Таймер», «Запуск проекта» вернут пусто.
* Файлы: `TextFileOpen(name,'',fomAppend,fcpUTF8); TextFileWriteLn(S); TextFileClose;`
* Звук: `PlayAlarmSoundAll`, `StopSoundAll`.
* Объекты из скрипта: `Field1.AllowInput := False;`, `Shape1.Color := clRed;`,
  `Tank1.Visible := False;`, `Text1.Text := ...`.
* В версии **Demo-64 штатный «Журнал действий оператора» недоступен** — протокол
  действий приходится писать самому в текстовый файл.
